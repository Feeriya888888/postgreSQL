# Аналитика продаж интернет-магазина (PostgreSQL)

Портфолио-проект по SQL: учебная база данных интернет-магазина и 25 аналитических запросов,
написанных под PostgreSQL. Все запросы проверены на живых данных, результаты лежат в CSV.

## Состав проекта

| Файл | Что внутри |
|------|-----------|
| `01_schema_postgres.sql` | Схема БД: 4 таблицы, типы PostgreSQL (`IDENTITY`, `NUMERIC`, `CHECK`), индексы, в т.ч. функциональный |
| `02_data_postgres.sql` | Тестовые данные: 120 клиентов, 33 товара, 800 заказов (2023-01 ... 2025-06), ~2000 позиций |
| `03_queries_postgres.sql` | 10 базовых запросов: JOIN, GROUP BY, CTE, CASE, LATERAL |
| `04_window_functions_postgres.sql` | 10 запросов на оконных функциях |
| `05_postgres_features.sql` | Фичи, которых нет в MySQL/SQLite: DISTINCT ON, FILTER, generate_series, GROUPING SETS, INTERVAL |
| `*.csv` | Результаты каждого запроса (query_01..10, w01..10, a01..05) |

## Схема данных

- `customers` — клиенты: имя, email, город, дата регистрации
- `products` — товары: категория, цена
- `orders` — заказы: клиент, дата, статус (`delivered` / `in_transit` / `cancelled`)
- `order_items` — позиции заказов: товар, количество, цена продажи (может отличаться от прайса)

Выручка во всех запросах считается только по доставленным заказам.


## Ключевые выводы по данным (снимок на 2025-06-30)

- Общая выручка (доставленные заказы): ~38,7 млн
- Лидер продаж: ноутбук UltraBook 14 (~6,6 млн)
- «Электроника» — главная категория, ~56% выручки
- Повторных покупателей: 81% из 100 активных клиентов
- Топ-20 клиентов дают 51,5% выручки — классический «парето-эффект»
- 46 клиентов не покупали дольше 90 дней — кандидаты на реактивацию

## Что покрыто технически

- Оконные функции: `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`, `LEAD`, `NTILE`, `SUM/AVG/COUNT OVER`, фреймы (`ROWS BETWEEN ...`), `FIRST_VALUE`, `LAST_VALUE`, `PERCENT_RANK`, `CUME_DIST`
- Именованные окна (`WINDOW w AS (...)`)
- CTE и вложенные подзапросы
- `LATERAL` join, `FILTER`, `DISTINCT ON`, `generate_series`, `GROUPING SETS`
- Ограничения целостности: `CHECK`, `UNIQUE`, `REFERENCES`, индексы под аналитику

## Известные ловушки (разобраны в комментариях)

1. Алиас оконной функции нельзя фильтровать в `WHERE` — нужен CTE или подзапрос.
2. `LAST_VALUE` без фрейма смотрит только до текущей строки — нужен `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`.
3. `RANK` и `DENSE_RANK` дают разные номера при ничьих — разница показана на одних данных (w02).

## Данные

Данные синтетические и детерминированные (задан seed) — результаты воспроизводимы.
Распределение заказов по клиентам намеренно сделано неравномерным (парето-эффект), как в реальных магазинах.
